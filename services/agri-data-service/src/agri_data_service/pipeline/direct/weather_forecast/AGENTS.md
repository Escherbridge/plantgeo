# Local fixture forecast slice

This directory implements the current session's explicitly authorized deterministic local
fixture exception. It is not an admitted Open-Meteo product. No network, PostgreSQL, object
store, shared availability registration, scheduler, production HTTP profile or deployment
is authorized here. The standalone HTTP adapter is the user's requested reviewable local
boundary, deliberately unmounted from `interface/http/parquet_routes.py` and application
profiles. The warehouse schema is intentionally unregistered: the existing forecast schema
extension requires stochastic provenance inappropriate for this deterministic provider
product, and shared lane ownership remains untransferred. No foundation module was added.

`warehouse/parquet/weather_forecast_arrow.py` declares the narrow typed interface to the
installed Arrow library, which ships without Python type information in this environment.
Its explicit module casts terminate that external typing boundary; table data still enters
the reader as `object` rows and must pass exact schema/source/value reconciliation before
the reader promotes it to `ForecastRow`. No untyped import suppression or `Any` is added.

The current session owns only the two explicit test-catalogue entries in
`tests/direct/test_direct_writer_contract.py` and `test_direct_package_registration.py`.
They record this synthetic non-production writer exception in the default-deny inventories;
they do not transfer or modify any runtime lane, availability or executor registration.

## Frozen product

`weather-forecast/v1` is generated by `PlantGeo fixture`, model
`deterministic-fixture-v1`, licensed CC0-1.0 as synthetic project-authored values.
Run IDs encode an explicit hourly UTC initialization. Every lifecycle timestamp uses the
synthetic fixture clock and is labelled accordingly; these are not measured production
fetch/admission/publication instants. The default fixture is September 12 2026 00:00 UTC,
covering 72 hourly valid instants through September 15 00:00 exclusive.

Only four exact WGS84 sample coordinates exist: (lat, lon) (40,-105), (40.1,-105),
(40,-104.9), (40.1,-104.9). No radius snap, native-grid footprint or interpolation is
claimed. Field reads return these samples inside a bbox, never polygons. Zoom is resolved
by the shared rung mechanism and disclosed without implying spatial generalization.

The warehouse module freezes units, ranges and statistics for temperature, humidity,
clouds, precipitation and wind u/v/speed/direction. Heights are 2 m for temperature/humidity
and 10 m for wind; cloud is total cover. Wind is earth-relative, meteorological direction
from true north clockwise. Daily wind uses mean components, then speed/direction; a mean
speed under 0.01 m/s has undefined direction. It never averages scalar bearings.
Precipitation represents [valid,valid+1 hour); instantaneous variables represent `valid`.
Hourly card intervals describe the precipitation interval only. UTC day summaries require
24 values per variable; partial sums are null, never full-day-looking partial totals.
Cloud at the first sample at lead 6 is explicitly `synthetic-source-missing`. Zero rain is
a numeric value in the synthetic product, not missingness. There are no
probabilities, ensemble members, calibrated confidence intervals or uncertainty estimates.

## Publication and bounded recovery

The writer uses the existing canonical JSON/SHA functions and `AvailabilityStorage` port
shape (`StoredAvailabilityObject`, immutable put, ETag compare-and-swap). A filesystem
adapter implements the port under one explicitly supplied local root, atomic replacement
and file locks. It does not execute shared PostgreSQL coordination. Source bytes and the
typed long-form Parquet artifact are immutable. The manifest binds all required variable,
sample, time, row, size and SHA identities. Completeness is written last; only then can
`current.json` advance conditionally. Replay reconstructs the same bytes and completes an
interrupted stage; it refuses a conflict and never moves a newer pointer backward.
Readers use explicit run IDs, so a newer pointer cannot mix a series or substitute a run.

This local run pointer is not the existing day/rung availability index. Importing its
storage protocol type reuses a port, not the publication duties. Run-aware production
availability and durable forward/repair/status duties remain an explicit owner handoff.
No automatic pruning is provided; local artifacts retain all published and staged runs.

Reads cap the complete product at four points, 72 hours, 2,304 long-form values and 2 MiB
per artifact, declared uncompressed Parquet body and response. They verify completion,
manifest/source/Parquet hashes and reconcile every actual Parquet value to the deterministic
source, including schema, identity, intervals and gaps. All HTTP and agent entry points use
the existing `run_bounded_read` concurrency admission. Exact-window and field requests
refuse limits; they never silently truncate. A stale run, absent completeness marker,
outside-domain sample and integrity refusal are distinct states. Production upstream
unavailability is not fabricated by this local adapter. The fixture is stale at its horizon
end; tests inject an explicit clock, while HTTP uses the real clock.

## Local invocation

From `services/agri-data-service`, with the project Python environment:

```powershell
python -m agri_data_service.pipeline.direct.weather_forecast.adapter --root .local/weather-forecast
python -m agri_data_service.interface.http.weather_forecast --root .local/weather-forecast --port 8097
```

Point `WEATHER_FORECAST_LOCAL_URL` in the local Next process at `http://127.0.0.1:8097`.
The explicit fixture page and proxy own their separate feature files; no main map layer,
tRPC registry or agent/MCP registry changes occur before ownership transfer.
